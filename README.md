# uv2800 —— 一加 13 电池解容模块

这是一个给一加 13（OnePlus 13 / PJZ110）做的 KernelSU 模块。它通过内核挂钩和投票器覆写，把系统的关机截止电压往下调，让手机在自动关机前多放出一段原本被锁住的电量；同时把电量计（ADSP QBG）的“空电点”跟着一起改掉，保证关机电压调低之后，剩余电量百分比和容量统计依然算得准。

当前版本 **v12**（`version=12` / `versionCode=35`），支持 ColorOS 15、16、17。这一版内置了完整的原生 KernelSU WebUI，调电压、开关附加功能、看实时状态和恢复原厂都能在管理器界面里直接点按完成。

> **卸载提醒**：卸载前请先确认电量大于 30%（单芯电压高于 3.30 V），打开模块 WebUI 点一次 **「恢复原厂」**，成功后再卸载模块。直接删除模块会留下已经改写进电量计的底层参数，完整步骤见下文[恢复原厂与卸载](#五恢复原厂与卸载务必按顺序)。

## 一、它到底改了什么

### 1. 关机截止电压可以自己定

一加 13 用的是硅碳负极电池，硬件放电下限在 2800 mV 左右，但原厂随着循环次数增加会把关机电压和空电点抬高到 3200–3250 mV 甚至更高，电池明明还有电就提前关机了。

模块通过内核挂钩（`kprobe`）和投票器覆写（`vote_override`），把驱动的关机阈值直接锁定为你设定的关机电压 `V_s`。默认 **2800 mV**，可以在 **2800–3060 mV** 之间自由调整。

### 2. 电量计的空电点跟着一起改

只改关机电压而不改电量计的空电点（`deep_term_volt`，也就是电量计认为的“0%”），会导致电量百分比计算失真。模块会按下面的公式根据关机电压自动派生出学习终止电压，主动写进 ADSP 电量计，并同步锁定 TERM 投票器：

```text
ADSP 终止电压 = 关机电压 − max(0, 3060 − 关机电压)
```

在 2800–3060 mV 解耦区间内，它等价于 `2 × 关机电压 − 3060`（按默认的 2800 mV 关机电压算，ADSP 终止电压就是 2540 mV）；而在恢复原厂（电压 ≥ 3060 mV，比如 3250 mV）时，内核会自动保持原厂值本身，不会把它放大。

> **注意**：电量计**只在满电状态发生切换时**（充到 100% 满充，或满电时拔插充电器）以及后续充放电循环中重新锚定全充容量（FCC）。刚改完电压时容量上限不会立刻跳变，踏踏实实充满一次电就能看到效果。

### 3. 显示真实电量（可在 WebUI 独立开关，默认开启）

官方状态栏电量走了一层平滑算法，玩游戏等高负载放电时会明显滞后于实际电量。模块把电量计的真实电量（`chip_soc`）通过 `bind-mount` 直接挂载到系统的 `capacity` 节点上，去掉平滑滞后。如果你更习惯官方的慢速平滑显示，可以在 WebUI 里单独关掉它。

### 4. 禁止 1% 强制超级省电（可在 WebUI 独立开关，默认开启）

系统默认在电量掉到 1% 时强制弹窗切进超级省电模式。模块通过 OPPO 的设备策略接口（`oplus_diable_super_power_saving_mode`）把这条限制关掉，让 1% 电量下也能正常用手机。这项功能同样支持在 WebUI 里单独开关。

## 二、支持情况

模块在下面这些 ROM 和内核上做过真机回归测试，用的是 [自动化测试矩阵/](自动化测试矩阵) 里的自动化用例（共 33 条）：

| 系统版本 | 内核版本 | 标准加载（LKM） | 越狱注入（late-load） |
|---|---|---|---|
| ColorOS 15 `15.0.0.821` | 6.6.30 | 通过 31 条 | 通过 28 条 |
| ColorOS 15 `15.0.0.861` | 6.6.66 | 通过 31 条 | 通过 28 条 |
| ColorOS 16 `16.0.5.701` | 6.6.89 | 通过 31 条 | 通过 28 条 |
| ColorOS 16 `16.0.10.501` | 6.6.118 | 通过 31 条 | 通过 28 条 |
| ColorOS 17 `17.0.0.101` | 6.6.118 | 通过 31 条 | 通过 28 条 |

说明：

- 33 条用例里，标准加载路线适用 31 条（另外 2 条是越狱专属），越狱注入路线适用 28 条（另外 5 条是标准加载专属）。
- 模块内置了针对 ColorOS 15（2 个电压投票器、指针型 setter）与 ColorOS 16/17（4 个电压投票器、值型 setter）的双 Profile 自适应机制。
- 加载时还会逐条核对驱动里的 4 处关键指令字，任何一条对不上就直接**拒绝加载**——宁可不生效，也绝不在未知内核上乱改寄存器。

## 三、安装

1. 手机需要已经获取 Root 权限，并装好 **KernelSU**（或兼容 KernelSU WebUI 的管理器）。
2. 在管理器里刷入构建好的模块包（Release 页面下载的 `op13-battery-unlock.zip`，或本地构建生成的 `一加13解容-v12.zip`）。
3. 重启手机。
4. 完整充一次电（充到 100%，或满电时拔插一次充电器），让电量计按新的空电点重新计算容量。

模块同时支持 KernelSU 随开机加载（标准 LKM 模式）和系统启动后注入（越狱 late-load 模式）。越狱模式下模块会自动通过触发一次无副作用的驱动调用来捕获电量计设备指针，全程不需要插拔充电器。

## 四、日常使用

### 1. 通过 WebUI 操作（推荐）

在 KernelSU 管理器的模块卡片上直接点开 **WebUI**，所有日常操作都能在界面里完成：

- **看实时状态**：顶部主卡和运行状态网格会显示电量计真实电量、系统显示电量、单芯电压、温度、当前关机电压 `V_s`、ADSP 空电点、剩余电量（RM）以及电量计真实全充容量（FCC，自动兼容 ColorOS 15/16/17 读取真值）。
- **调关机电压**：拖动滑块或点击 `2800` / `2900` / `3000` / `3060` 快捷按钮，点 **「应用并重跑 service.sh」** 即可立即生效，不需要重启手机。
- **开关附加功能**：「显示真实电量」和「禁止 1% 强制超级省电」两个开关可以随时独立切换，修改后会跨重启持久保留，且切换时只改对应功能，不会重复读写 ADSP。
- **高级诊断与看日志**：展开底部的「高级 / 日志」面板，可以直接查看 `uv2800.log` 的最新日志、手动捕获设备指针、只读 ADSP 硬件真值，或在勾选确认后手动向 ADSP 写入指定测试电压。

### 2. 通过配置文件或命令行操作

如果你习惯用终端或脚本，也可以直接读写状态目录 `/data/adb/uv2800_backup/` 或调用 CLI 入口 `/data/adb/modules/uv2800/webui.sh`：

```sh
# 查看完整状态快照（ASCII KEY=VALUE 格式）
sh /data/adb/modules/uv2800/webui.sh status

# 修改关机电压为 2900 mV 并立即应用
sh /data/adb/modules/uv2800/webui.sh apply 2900

# 单独开关真实电量（1=开启，0=关闭）或超级省电策略（on/off）
sh /data/adb/modules/uv2800/webui.sh set-real-soc 1
sh /data/adb/modules/uv2800/webui.sh policy on

# 查看运行日志
cat /data/adb/uv2800_backup/uv2800.log
```

## 五、恢复原厂与卸载（务必按顺序）

**请不要在没有恢复原厂的情况下直接删除模块。** 因为写进电量计 ADSP 寄存器的终止电压是跨重启保留的，直接卸载模块并不会把电量计内部的值改回原厂。

正确的卸载顺序：

1. **确认电量大于 30%（单芯电压高于 3.30 V）**
   如果在低电量（电池电压低于原厂终止电压，比如 3250 mV）时把原厂值写回电量计，电量计会立刻判定电池已经放空并进入钳位状态（电量卡在 0%，需要充满一次才能恢复）。WebUI 在检测到低电压或低电量时也会主动拦截提醒。
2. **在 WebUI 中执行「恢复原厂」**
   打开模块 WebUI，在「恢复原厂」卡片中勾选 **「我已知晓：低电量恢复可能让电量计钳位」**，点击 **「恢复原厂」**（或者在终端执行 `sh /data/adb/modules/uv2800/restore.sh`）。
   模块会优先读取首次修改前备份的原厂值（若无备份则按当前循环次数与温度从设备树精确算出原厂值），写回 ADSP 电量计，同时解绑真实电量挂载并恢复超级省电策略。
3. **卸载模块并重启**
   看到「恢复原厂完成」的提示后，回到 KernelSU 管理器勾选卸载本模块，然后重启手机即可。

> 补充说明：如果恢复原厂后你不想卸载，只是想暂时停用解容，保持原厂模式即可；以后想重新启用时，在 WebUI 里选好关机电压点 **「重新启用并应用」** 就能随时切回解容模式。

## 六、已知限制

- **`gauge_type == 1` 的分支未复刻**：厂商驱动在 `gauge_type == 1`（BQ27411 硬件）时会用 SOH 覆盖除数，一加 13 本机为 ADSP 电量计，模块里的 `uv_dt_orig` 没有复刻该外置分支。
- **异常拒绝与降级路径仅做静态与沙盒验证**：加载期指令字不匹配时的拒绝加载路径（`-EINVAL` / `-ENOENT`），以及未匹配到 Profile 时只注册显示挂钩的降级路径，在真机正常驱动上不会触发。
- **长期断电的持久化边界未测**：电量计写入值在手机彻底断电或长期闲置后的保持边界未做专门实测。

## 八、从源码构建

如果只修改用户态脚本或 WebUI 前端，直接将 `模块源目录/` 下的文件打包成 zip 即可（仓库里的 `模块源目录/uv2800.ko` 已经是最新编译好的二进制）。

如果要修改 [内核源码/uv2800.c](内核源码/uv2800.c) 并重新编译 `.ko`，需要 Linux 环境、LLVM 18 工具链以及约 2 GB 磁盘空间：

```sh
# 1) 拉取上游内核源码树（约 1.6 GB）
./fetch-kernel.sh

# 2) 首次构建前，按 THIRD-PARTY-NOTICES.md §1.4 准备内核树
#    （拷入编译前置/device_config，跑 olddefconfig 和 modules_prepare，拷入 Module.symvers）

# 3) 编译 uv2800.ko、同步进模块源目录并打包 zip
./自动化测试矩阵/build.sh
```

编译完成后，`build.sh` 会自动检查 `modinfo` 的 `vermagic` 以及 `.gnu.linkonce.this_module` 节大小（应为 `000600`），并在仓库根目录生成 `一加13解容-v12.zip`。
