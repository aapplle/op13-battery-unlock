# uv2800 —— 一加 13 电池解容模块

这是一个给一加 13（OnePlus 13）用的 KernelSU 模块。它把系统的关机截止电压往下调，让手机在自动关机前多放出一段电；同时把电量计的"空电点"一起改掉，保证关机电压调低之后，剩余电量百分比还算得准。

当前版本 **v11**（`version=11` / `versionCode=36`），支持 ColorOS 15、16、17。

当前源码含尚待真机验收的修复，下面的兼容性表是已发布 v11 的历史记录。修改内核源码后须重新构建；打包流程会校验 `uv2800.build.json`，缺少构建清单或 `.ko` 与源码不匹配时停止打包。

> **「执行」现在是一键安全卸载：恢复并校验成功后自动安排删除，再重启即可。** 完整步骤见[一键安全卸载](#五一键安全卸载)。

## 一、它到底改了什么

### 1. 关机截止电压可以自己定

原厂的关机电压留了比较大的安全余量，电池还有电就关机了。模块通过内核挂钩把驱动算出的关机电压直接替换成你设定的值，默认 **2800 mV**，可调范围 **2800–3060 mV**。

### 2. 电量计的空电点跟着一起改

只改关机电压是不够的：电量计如果不认这个新的空电点，它算出来的剩余电量就是偏的。模块会按下面的公式把 ADSP 的终止电压（`deep_term_volt`，也就是电量计认为的"0%"）一起改掉：

```
ADSP 终止电压 = 关机电压 − max(0, 3060 − 关机电压)
```

按默认的 2800 mV 关机电压算，ADSP 终止电压就是 2540 mV。

> 这里有个前提：电量计**只在满电状态发生切换时**才重新计算全充容量（充到 100%，或者满电时拔插充电器）。刷入后完整充满一次，效果才会体现出来。

### 3. 取消 1% 强制超级省电

系统在电量掉到 1% 时会强制切进超级省电模式。模块通过 OPPO 的设备策略接口（键名 `oplus_diable_super_power_saving_mode`）把这条限制关掉。

### 4. 显示真实电量

系统显示的电量走了一层平滑处理，高负载放电时会明显滞后于实际电量。模块把电量计的真实值（`chip_soc`）直接挂载到系统的 `capacity` 节点上，让状态栏显示的就是电量计读到的值。

## 二、支持情况

模块在下面这些 ROM 和内核上做过真机测试，用的是 `自动化测试矩阵/` 里的自动化用例（共 33 条）：

| 系统版本 | 内核版本 | 标准加载 | 越狱注入 |
|---|---|---|---|
| ColorOS 15 `15.0.0.821` | 6.6.30 | 通过 31 条 | 通过 28 条 |
| ColorOS 15 `15.0.0.861` | 6.6.66 | 通过 31 条 | 通过 28 条 |
| ColorOS 16 `16.0.5.701` | 6.6.89 | 通过 31 条 | 通过 28 条 |
| ColorOS 16 `16.0.10.501` | 6.6.118 | 只跑了 T10 子集（7 条） | 通过 28 条 |
| ColorOS 17 `17.0.0.101` | 6.6.118 | 通过 31 条 | **未实测** |

说明：

- 33 条用例里，标准加载路线适用 31 条（另外 2 条是越狱专属），越狱注入路线适用 28 条（另外 5 条是标准加载专属）。两条路线都没出现过失败。
- 6.6.118 有两个不同的内核构建，ColorOS 16 和 ColorOS 17 的结果不能互相套用。

模块在加载时会校验驱动里的关键指令，显示挂钩签名不匹配时停止加载。ADSP profile 不匹配时只保留两个显示/关机电压挂钩，并关闭 ADSP 读写接口；关键挂钩注册失败时撤销所有已注册挂钩。这些检查覆盖已知挂钩位置，未知系统仍需单独验证。

## 三、安装

1. 手机需要已经 Root，并且装好 **KernelSU** 管理器。
2. 用管理器刷入构建好的模块包 `一加13解容-v11.zip`。
3. 重启手机。
4. 完整充一次电（充到 100%，或满电时拔插一次充电器），让电量计重新计算容量。

模块同时支持两种加载方式：KernelSU 随开机加载（标准加载），以及越狱注入（late-load）。两种方式下模块的功能是一样的，区别在开机时脚本由谁触发。

## 四、日常使用

### 改关机电压

编辑手机上的这个文件：

```
/data/adb/uv2800_backup/target_mv
```

写一个纯数字（单位 mV），范围 2800–3060。保存后重启手机，开机会自动重新计算并写入对应的 ADSP 终止电压。

数值越小，放电越深。填超出范围的值会被回退成默认的 2800。

### 看运行日志

```
/data/adb/uv2800_backup/uv2800.log
```

模块的每一步操作都会写进这个文件，同时也往内核日志（`dmesg`）里写一份。遇到问题先看它。

## 五、一键安全卸载

使用 `versionCode=35` 或更新版本时：

1. **先充电，建议电量大于 30%。** 脚本要求单芯电压至少 3.3 V，且高于恢复目标；电压不足或读数缺失时停止操作。
2. 打开 KernelSU 管理器，找到本模块，点 **「执行」** 按钮。
   脚本恢复电量计参数、设备策略和电量显示，实时校验成功后自动安排卸载。
3. 看到 **一键安全卸载已安排** 后重启手机。无需再点一次管理器的删除按钮。

失败时不新增删除标记，保留恢复记录并说明原因；充电或排除故障后重试。若此前已用管理器安排删除，一键流程会先尝试撤销旧标记，确认撤销成功才继续。`restore_pending` 表示恢复尚未完成；`uninstall_verified` 记录安排卸载前的成功校验，历史 `adsp_state` 不代替实时读回。

`versionCode=36` 起，手动恢复、开机重试和在线卸载共用同一恢复流程。目标来自当次设备树与运行数据计算，结束前再次复核；过期备份不再决定写入值，实时计算失败时停止。电压、硬件读回、策略读回或挂载检查任一失败，都保留待恢复状态。`restore_target_mv` 保存最近一次完整恢复通过的目标，`adsp_orig.txt` 只作历史诊断。

**为什么不直接用垃圾桶？** 删除模块文件不会自动撤销此前写入电量计的参数。KernelSU 的普通卸载先写删除标记，通常到下次开机才执行 `uninstall.sh`；脚本返回失败也不阻止随后删除模块目录。那时内核接口可能已不在，不能把它当作恢复的最后保障。

“直接删除一定会留下失配参数”过于绝对：驱动也可能在启动或后续状态切换时重写参数，具体持久化边界仍待验证。本模块把校验放在安排删除之前，避免依赖这种未确定的恢复行为；实际 `rmmod`、重启和删除磁盘文件也不是同一个操作。

只想恢复、不卸载时，在手机 Root Shell 中使用：

```sh
sh /data/adb/modules/uv2800/action.sh --restore-only
```

取消已安排的卸载可使用管理器的撤销功能。取消后保留恢复态；重新启用解容仍需按日志提示清理 `skip` 并重启。旧版本的「执行」只恢复，仍需再手动安排卸载。

## 六、已知限制

- **旧策略数据的迁移语义。** 新版只通过 Binder 修改本模块的目标键，解析异常/方法返回并读回确认，不覆盖或删除共享 XML。新版记录原键的 true/false/缺失；旧版没有独立原键记录时明确按默认 false 迁移，原键缺失也恢复为显式 false（默认效果相同，存储状态不同），日志会注明。损坏的 `orig_state` 会停止恢复并保留资料。
- **`gauge_type == 1` 的机型没覆盖。** 厂商驱动在那种情况下会用 SOH 覆盖除数，模块里的原厂值推算没有复刻这一分支。
- **加载期校验的拒绝路径没有真机用例。** 也就是说，"驱动指令对不上时拒绝加载"这个行为本身没在真机上验证过。
- **profile 切换的降级路径没有真机用例。** 没匹配到 profile 时模块只注册显示相关的挂钩，这条路径也没在真机上跑过。
- **电量计写入值的持久化边界没测。** 断电或长期没电之后会不会回落到默认值，没有结论。

## 八、从源码构建

需要：Linux 环境、LLVM 18 工具链、Python 3、约 3 GB 空闲磁盘。GitHub Actions 使用 Ubuntu 24.04；其完整 apt 依赖见 [构建工作流](.github/workflows/release.yml)。手机侧的状态操作需要可用的 `flock`（支持系统命令及 KernelSU/Magisk BusyBox、Toybox）；缺少锁后端时脚本会停止操作并记录原因。

```sh
# 1) 拉取固定内核及原始链接需要的 OEM 子树（按需稀疏检出）
./fetch-kernel.sh

# 2) 写入 device_config，运行 olddefconfig/modules_prepare，核验配置并复制 Module.symvers
bash 自动化测试矩阵/prepare-kernel.sh

# 3) 编译并打包
自动化测试矩阵/build.sh
```

`build.sh` 会做这几件事：把 [内核源码/uv2800.c](内核源码/uv2800.c) 编译成 `uv2800.ko`、复制进 [模块源目录/](模块源目录)、再从 [模块源目录/](模块源目录) 打包成仓库根目录下的 `一加13解容-v11.zip`。

编译在临时目录完成。同步 `.ko` 前会核验 AArch64 ELF、完整 vermagic 和 `.gnu.linkonce.this_module` 节区大小（必须为 `0x600`），并生成源码、内核配置、符号表、工具链和二进制摘要清单 `uv2800.build.json`；内核源码树必须精确匹配固定提交。

推送 `main`、提交 PR 或手动运行 Actions，都会执行宿主测试、拉取固定内核、准备配置、从当前源码编译并校验模块。Artifacts 提供安装包、`.ko`、构建清单、实际配置和 SHA256；失败时保留日志及 `olddefconfig` 配置差异。只有推送 `v*` tag 才会发布 Release。CI 编译成功后仍需真机矩阵验收；外部模块构建未生成 `vmlinux` 时，上游会跳过模块 BTF 生成并记录提示。

## 九、测试

无需手机的失败路径回归见 [host/README.md](自动化测试矩阵/host/README.md)，覆盖内核注册回滚、ADSP 调用隔离、恢复脚本及测试/构建工具。宿主测试通过后，仍需重新编译并运行下面的真机矩阵。

真机回归测试的入口是 [自动化测试矩阵/run.sh](自动化测试矩阵/run.sh)。它会先自动判断当前设备是标准加载还是越狱注入，再跑对应的用例，结果写到 `自动化测试矩阵/results/<时间戳>/`。

```sh
cd 自动化测试矩阵
./run.sh --list          # 先看有哪些用例
./run.sh                 # 跑当前路线适用的用例
./run.sh --with-reboot   # 标准加载下把需要重启的用例也跑完
```

详细的用法、用例清单和判读方法在 [自动化测试矩阵/README.md](自动化测试矩阵/README.md)。跨 ROM 的实测汇总在 [自动化测试矩阵/兼容性总表.md](自动化测试矩阵/兼容性总表.md)。

越狱注入路线还需要越狱工具，它同样不随仓库分发，用 [自动化测试矩阵/手机测试环境准备/fetch-ghostlock.sh](自动化测试矩阵/手机测试环境准备/fetch-ghostlock.sh) 拉取。
