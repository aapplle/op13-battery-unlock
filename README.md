# 一加 13 解容（op13-battery-unlock）

> **把一加 13（PJZ110）的关机截止电压从 3250mV 降到 2800mV，并让电量计【原生】按新的空电点重算 SOC。**
>
> 形态：1 个 28KB 内核模块（kprobe 运行时注入）+ 1 个 KernelSU 模块。
> **不刷 dtbo、不改任何分区、不碰 system/vendor，卸载无残留。**
>
> 支持 ColorOS 15/16/17，支持 KernelSU late-load（越狱 / 临时 root）模式。

---

## 太长不看

| 指标 | 原厂（term=3250）| 解容后（term=2600 解耦）|
|---|---|---|
| 关机电压 | 3250 mV | **2800 mV** |
| 满容量 fcc | 4346 mAh | **~5032 mAh（+15.8%）** |
| 0% 对应电压 | 2983 mV | **2865 mV** |
| 0% → 关机 | 217 mV / 9 分钟 | **83 mV / 0.9 分钟** |
| 显示 | 官方平滑，13W 放电滞后 13 个点 | 电量计真实值（bind-mount）|
| 低电量 | 强制进超级省电 | 已禁用（OPPO 设备策略）|

**代价**：装模块重启 1 次 + 满电状态下拔插一次充电器。卸载前需点一下模块的「执行」按钮。

## 一、原理

一加 13 的硅碳负极电池本身能放电到 2800mV，但官方把关机截止电压抬到 3250mV
（驱动内置默认值 `low_volt_mv=450`，2800+450=3250），中间 450mV 的容量被锁住。

整条链路在 `oplus_chg_v2.ko` 里，逆向后确认有**两个独立的控制点**：

| 控制点 | 决定什么 | 本方案做法 |
|---|---|---|
| `oplus_fg_get_deep_term_volt` 读到的值 | **关机电压** | kprobe 强制返回 2800 |
| 电量计 ADSP 里的 `deep_term_volt` 寄存器 | **电量计模型的空电点**（决定 fcc/SOC）| 硬件命令 `0x800A` 写 2600 |

这就是**解耦**：ADSP 写 2600 让电量计把模型下限压到 2600，关机仍由内核 hook 卡在 2800。

> **只改关机电压不改模型**，SOC 会在 3000mV 左右就显示 0%（这是只刷解容补丁的通病）；
> 两个都改，百分比才完整覆盖到 2800mV。

### 五层设计

```
① 内核 getter hook  → oplus_fg_get_deep_term_volt 内部：驱动读到的 term 固定 2800（决定关机电压）
② 内核 setter hook  → oplus_fg_set_deep_term_volt 内部：阻止驱动把 term 写回电量计
③ ADSP 写入         → service.sh 经 adsp_write 写 2600（命令 0x800A，只影响模型下限）
④ 显示层            → bind-mount chip_soc → capacity（VFS 级，去官方平滑滞后）
⑤ 策略层            → oplusdevicepolicy 禁超级省电（用户态，与内核无关）
```

### 为什么不用其它路线

- **改 dtbo**：目标参数不在实时 DT 里（是驱动代码内置默认值），且刷回原版 dtbo **不能**恢复电量计里已写入的值。
- **hook 显示层**（重映射百分比）：**实测判死**。SOC 是库仑计（电流积分），端电压 = OCV − I×R，
  10W+ 放电时端电压跌落 135~270mV，任何基于电压的重映射都会跳变 2~3 个点。
  **唯一正确的做法是让电量计原生重算 fcc。**

## 二、安装

### 前置

- 一加 13（PJZ110），ColorOS 15 / 16 / 17
- KernelSU（标准或 late-load 越狱模式均可）
- 电池电量充足（>50%）

### 步骤

```
1) 用 KernelSU 管理器刷入 一加13解容-v10.6.zip
2) 重启                                    ← 唯一需要的一次重启
3) 模块开机后自动写入电量计 term
   ⚠️ 越狱(late-load)模式：模块加载太晚，错过了驱动开机那次 vote，
      需【插拔一次充电器】触发 vote（getter 捕获回写指针 uv_dev，随后脚本主动 adsp_write 解耦）
      无时间限制，任意时刻插拔一次即可；不插拔不影响关机保护(2800mV)
      ★ 一次插拔双用：同一次开机内「安装解耦」与「卸载回写」共用这次捕获，
        无需重复插拔；但重启后需重新插拔一次
4) 触发一次满电状态切换（三选一）：
     · 充满一次
     · SOC=100 时拔掉充电器
     · SOC=100 时插上充电器
5) 电量计原生重算 fcc，完全生效 ✅
```

### 验证

```sh
cat /sys/class/oplus_chg/battery/vbat_uv            # 应为 2800
P=/sys/module/uv2800/parameters
echo 1 > $P/adsp_read; cat $P/adsp_read             # 2600（或 2800）
dmesg | grep "uv2800:"                              # v10 ready, 5 个 hook
dmesg | grep bs_update_data | tail -1               # fcc ≈5000 ★唯一可靠指标
```

> ⚠️ **不要用 `battery_fcc` 节点验证**：它每次读都实时查询 gauge IC，查询失败时
> （`oplus_get_gauge_type` 返回 `-ENOTSUPP`）会**回退到 `design_capacity`**，
> 显示的不是电量计真实 fcc。请用驱动 `bs_update_data` 日志里的 `fcc`。

## 三、卸载（顺序不能错）

```
1) 【必须】电量充足（>50%，电压 >3250mV）时点 KernelSU 模块的「执行」按钮
      → 自动算原值回写 + 恢复超级省电 + 恢复官方平滑显示
2) 删除模块 → 重启
3) 验证：cat /sys/class/oplus_chg/battery/vbat_uv   → 应显示原值（如 3250）
```

> ⚠️ **低电压回写会让电量计进入钳位态**（SOC 卡 0%，需充满一次才恢复）。
> 「执行」按钮里的回写目标**不是硬编码 3250**，而是实时读 DT 的 `term_coeff` 档位表 +
> 当前深度放电次数算出来的（COS15 档位不同，必须实时算）。

**如果只删模块不点按钮**：关机电压恢复 3250，但电量计里仍是 2600/2800 →
空电点低于关机点，**还有百分之几就关机**。恢复方法：重装模块 → 点按钮。

## 四、兼容性

| 层 | COS17 | COS16 | COS15 | 验证方法 |
|---|---|---|---|---|
| 内核符号 CRC | ✅ | ✅ | ✅ | 三版本 Module.symvers 实测一致 |
| 显示链挂钩点 | ✅ | ✅ | ✅ | 归一化反汇编逐指令比对 |
| getter/setter 挂钩点 | ✅ | ✅ | ✅ | profile 表 + 指令字签名 |
| setter ABI | (dev,int) | (dev,int) | (dev,int*) | profile `set_ptr` |
| 硬件命令 0x800A | ✅ | ✅ | ✅ | 反汇编确认 |
| 设备策略键 | ✅ 真机 | ✅ jar | ✅ jar | `oplus-services.jar` grep |
| 电量计 term→fcc 行为 | ✅ 真机 | ⚠️ 未验证 | ⚠️ 未验证 | ADSP 固件无法静态分析 |

**跨内核**：6.6.118 编译的 ko 可直接加载到 6.6.30 / 6.6.89（modversions CRC 三版本一致）。

### 失败安全

| 场景 | 行为 |
|---|---|
| 驱动更新导致指令字不匹配 | **拒绝加载**，手机正常开机（无 hook）|
| profile 不匹配 | 只注册 2 个显示 hook，ADSP 功能禁用 |
| KMI 变化（CRC 不匹配）| insmod 被内核明确拒绝 |

## 六、构建

需要一个与目标内核匹配的源码树 + 工具链。要点：

- 设备 `CONFIG_CFI_CLANG=y` 且未开 `CFI_PERMISSIVE` → 间接调内核函数必须
  `noinline + no_sanitize("kcfi")`，否则 `brk` → panic（**这个坑让测试机重启过两次**）
- `modversions` CRC 由类型签名决定、跨构建稳定 → 可手写 `Module.symvers`
- 走内核 Kbuild（`make M=`），不要手动 `ld.lld`
- kprobe 结构体全部做成文件级 `static`，避免引入额外符号

详见主文档 §4「踩坑清单」。

## 七、风险声明

- 2800mV 是硅碳负极的放电下限，**长期每次都放到自动关机会加速电池老化**，自行权衡；
- 电量计 term→fcc 重算行为在 COS15/16 上**未经真机验证**（ADSP 固件无法静态分析），
  最坏情况退化为「0% 提前」，不会损坏硬件；
- 驱动大版本更新后指令字可能变化 —— 模块会**拒绝加载**而不是乱 hook，此时需要重新适配；
- **刷机有风险**，请自行备份重要数据并确认能承受变砖后果。
